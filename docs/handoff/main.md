## 핸드오프 — main / 2026-11-18

**문제**: 분할매수 조건(Opportunity ≥ 70 · Trend ≥ 60 · 추세 개선)을 실제 매매 규칙으로
쓸 수 있는지 판단하려 했다.

**내린 결정**: 규칙으로 확정하지 않고 "매수 후보를 거르는 조건"으로만 쓴다. 판단 순서:

1. 기업의 투자 근거가 유지되는가 — 실적 전망·부채에 판단을 뒤집을 변화가 없는지
2. Opportunity가 왜 높은가 — 밸류에이션이 매력적인 것인지, 급락으로 RSI·스토캐스틱이 올라간 것인지
3. 추세가 개선 중인가 악화 중인가 — 같은 30점이어도 10→20→30과 70→50→30은 다른 상황이다
4. 총 투자 한도와 추가 매수 조건을 미리 정한다 — 가격이 내려갔다는 이유만으로 계속 추가하지 않는다
5. 투자 근거가 훼손되면 추가 매수를 중단한다 — 점수 충족 여부보다 우선한다

코드 변경이 없으므로 되돌릴 것이 없다.

**건드린 파일**: 없음 (판단 정리만)

**테스트**: 전부 통과 — 99개 (2026-11-18 확인, `PYTHONDONTWRITEBYTECODE=1`)

**다음 단계**:
1. 합성 데이터에서 드러난 조건 간 긴장을 실제 자료로 재확인한다. 합성 사인파에서는
   Opportunity ≥ 70이 103일, Trend ≥ 60이 101일, 둘 다 37일, 거기에 "추세가 5일 전보다
   상승"을 더하면 **0일**로 전부 탈락했다. `--improvement-sessions 20` 으로 늘리면 5일 통과.
2. `improvement_sessions` 기본값 5가 너무 엄격한지 실제 자료로 판단한다.

**막힌 지점**: Opportunity는 눌림에서 높고 추세 개선은 반등에서 참이라, 두 조건이 서로
다른 국면을 가리킨다. 이것은 코드 버그가 아니라 조건 설계 자체의 성질이다. 합성 사인파에서
가장 극단적으로 나타나므로 실제 데이터에서는 덜할 것으로 보이지만, 확인 전에는 모른다.
며칠간의 개선을 볼지는 아직 앱에 규칙으로 정의되지 않았다.

## 핸드오프 — main / 2026-11-18

**문제**: IREN은 forwardPE가 음수여서 밸류에이션 점수에 50이 대입된다. PBR과 EV/ARR 중
무엇을 쓸지 판단해야 했다.

**내린 결정**: **둘 다 점수 모델에 넣지 않는다.** 대신 두 가지를 했다 — Val 칩에 `(미측정)` 과
주황 배경으로 대입값임을 드러내고, EV/ARR은 점수가 아니라 패널에 **라이브 시장값으로 분리 표시**한다.
`config.WEIGHTS` 와 점수 공식은 건드리지 않았으므로 ADR-0003을 어기지 않는다.
되돌리려면 커밋 `1e13ab0` 을 revert하면 된다 — 점수 로직에 손대지 않았으므로 표시만 되돌아간다.

**건드린 파일**: `app.py` — Val 칩 표시 + EV 전달 / `fundamentals.py` — `arr_multiples()`
추가(순수 함수, 네트워크 안 탄다) / `tests/test_app.py`, `tests/test_fundamentals.py`

**테스트**: 전부 통과 — 당시 64개, 2026-11-18 재확인 99개. 변이 검증 5건 전부 실패 확인
(`(미측정)` 제거 / 대입 판정 항상 False / EV·ARR 구간 삭제 / ARR 분모 1.0e9→2.0e9 / NaN 가드 제거).
테스트가 실제 버그를 하나 잡았다 — NaN 가드가 없어 `nanx` 가 렌더될 수 있었다
(yfinance는 결측을 NaN으로 주고, `NaN <= 0` 은 False라 게이트를 통과한다).

**다음 단계**:
1. 이 근거를 ADR로 승격한다 — 아래 "막힌 지점"의 숫자가 ADR-0003의 적용 사례다.
2. 적자기업 밸류에이션을 몇 점으로 볼지는 여전히 미결정. 투자 판단이므로 ADR을 먼저 쓴다.

**막힌 지점**: 왜 EV/ARR도 점수에 못 들어가는지가 기록돼 있지 않다. 근거는 이렇다 —
- 개념으로는 EV/ARR이 타당하다. IREN의 자산은 계약을 매출로 바꾸는 수단이고, 추적하는
  논리가 그 전환(Contract-to-Cash)이므로 EV/ARR이 그걸 직접 측정한다.
- PBR은 검증하려는 것을 전제에 넣는다. "장부에 적힌 만큼 값어치가 있다"고 가정하는데,
  IREN은 FY26 손상차손 **$638.8M** 이 바로 "장부가 ≠ 실제 가치"의 증거다.
- 그런데 EV/ARR은 분모를 고르는 순간 답이 4배 갈린다:
  EV $15.9B ÷ Operating ARR $1.0B = **15.9x**(비싸다) vs ÷ 계약 ARR $4.0B = **4.0x**(싸다).
  계약 ARR $4.0B은 아직 가동되지 않았고 가동 일정이 연기됐다. 연기된 ARR로 "싸다"를
  계산하면 연기 위험을 할인에 반영하는 게 아니라 **보상하게 된다** — 일정이 밀릴수록
  분모가 그대로 남아 계속 싸 보인다.
- 수동 갱신 데이터를 점수에 넣으면 점수 변동이 시장 변화인지 내 입력 시점 차이인지
  구분할 수 없다. 그리고 ARR이 있는 종목은 IREN뿐이라 종목 간 비교가 깨진다.
  둘 다 ADR-0003의 근거와 같다.

라이브러리뿐이다. 색은 dataviz 스킬 기준 팔레트 슬롯 1·2, 라이트·다크 양쪽 토큰을 명시하고

**건드린 파일**: `scripts/plot_equity.py`, `tests/test_plot_equity.py`,
백테스트 출력에 `buy_hold` 곡선 추가. 커밋 `ca893bd`(2026-11-08) → `c69e85b`(2026-11-14).

**테스트**: 전부 통과 — 99개 (2026-11-18 확인)

**다음 단계**:

**막힌 지점**: 세 가지를 의도적으로 남겼다 —

  지키는 것처럼 보인다.
- 축 눈금 색 `#898781` 은 라이트에서 3.50:1. 팔레트가 축·라벨용으로 못박은 값이고 축을
  뒤로 물리는 건 의도된 선택이므로 바꾸지 않았다. 올리려면 팔레트 쪽 결정이 먼저다.
