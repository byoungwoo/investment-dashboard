# ADR-0001: Macro 입력에서 0은 결측이 아니라 데이터로 취급한다

- 날짜: 2026-10-11
- 작성자: 이병우
- 상태: 유효
- 출처: 02e0919 `test: pin Macro Score v2.3 formula and stop treating 0% as missing data`

## 맥락

`macro_score()` 가 매크로 입력에 기본값을 끼울 때 `or` 를 썼다:

```python
ffr = macro.get("ffr") or 5.25
```

Python에서 `0.0` 은 falsy다. 따라서 **정책금리 0.00% 가 들어오면 결측으로 간주되어 5.25로
갈아끼워졌다.** 정책금리 0%는 2008~2015년과 2020~2022년에 실재했던 값이고,
TIPS 10Y 실질금리도 0 근방과 마이너스를 지났다.

영향: 그 데이터가 들어오면 `ffr_s` 에 **78.7점 오차**가 났다. `ffr_s` 는 Fed Policy Signal의
35% 비중이고, Fed Policy Signal은 평시 Macro Score의 20%(VIX>25 스트레스 국면 30%)를 차지한다.

더 나쁜 점: Macro Score v2.3 공식 전체에 테스트가 **하나도 없었다.** 가중치를 잘못 바꿔도
당시 36개 테스트가 전부 통과했다.

## 결정

1. `_or_default(value, default)` 를 도입하고 **`None` 일 때만** 대체한다. `0.0` 은 통과시킨다.
   NaN도 통과시켜 `_clamp()` 가 터뜨리게 둔다 — 조용히 잘못된 점수를 내는 것보다 멈추는 쪽이 낫다.
2. 공식을 테스트로 **못 박는다**: `tests/test_macro_score.py` 13개.
   - Rate Level = 10Y 75% + 30Y 25%
   - Fed Policy = (FFR vs r\*) 35% + (2Y Δ) 25% + (TIPS 10Y) 40%
   - Macro = Rate 80% + Fed 20% / **VIX > 25 → 70% / 30%**
   - 경계: VIX 25.0은 평시(초과만 스트레스), r\*는 `config.NEUTRAL_RATE`(2.5), NaN은 ValueError, 0~100 범위

## 근거

- 기대값은 **전부 손계산해 주석에 남겼다.** 코드를 다시 호출해 비교하면 공식이 바뀔 때 양쪽이
  같이 바뀌어 아무것도 못 잡는다
- 변이 12종을 심어 전부 잡히는 것을 확인했다
- 오늘 실제 값(FFR 3.88%)에서는 점수가 바뀌지 않는다 → 회귀 없는 수정

## 검토한 대안과 기각 이유

- **`if "ffr" in macro` 로 키 존재만 확인** — fetcher가 키를 넣고 값에 `None` 을 담는 경로가 있어 미해결
- **결측도 NaN으로 통일해 전부 터뜨리기** — 매크로 일부가 비어도 대시보드는 떠야 한다. 기각
- **0을 계속 기본값으로 대체** — 제로금리 구간 데이터를 영구히 왜곡한다. 기각

## 결과

`or` 기본값 패턴은 이 리포에서 금지다. 되돌리려면 `scorer.py` 의 `_or_default()` 를 제거해야 하고,
그 순간 `tests/test_macro_score.py` 가 실패한다. 공식 자체를 바꾸려면 해당 테스트의
**손계산 주석까지 함께** 갱신해야 한다 — 그게 의도된 마찰이다.
