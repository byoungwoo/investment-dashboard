# ADR-0003: 공시 스냅샷은 점수 모델에서 분리한다

- 날짜: 2026-09 ~ 2026-10 (기록: 2026-10-19)
- 작성자: 이병우
- 상태: 유효
- 출처: 1509c13 `feat: add fundamental detail dialogs`, 93d940b `feat: add ORCL to portfolio and gate fundamental detail button`

## 맥락

`fundamentals.py` 의 `FUNDAMENTAL_DETAILS` 는 **손으로 입력한 공시 스냅샷**이다.
전 종목이 있는 것도 아니고, 갱신도 수동이다 (현재 ABB 2026-07-16 ~ AVGO 2026-09-02).
이걸 Price Score에 넣고 싶은 유혹이 있다 — 실제 펀더멘털이니까.

## 결정

**넣지 않는다.** 스냅샷은 상세 UI 전용이고, Price Score / Grade / Action / Shadow 모델과
의도적으로 분리한다 (`fundamentals.py` 주석에 명시).

점수 가중치는 자동 수집 데이터만 쓴다: `valuation` 0.50 + `technical` 0.30 + `macro` 0.20.

스냅샷이 없는 종목은 `has_fundamental_detail()` 가드가 상세 버튼을 렌더하지 않는다.
가드가 없으면 `show_fundamental_detail()` 에서 KeyError가 난다.

## 근거

- 갱신 주기가 종목마다 다른 수동 데이터가 점수에 들어가면, **점수 변동이 시장 변화인지
  내 입력 시점 차이인지 구분할 수 없게 된다**
- 5종목 중 1종목(ORCL)은 스냅샷이 아예 없다. 결측 종목의 점수를 어떻게 매길지에 대한
  답이 없는 상태로 모델에 넣으면 종목 간 비교가 깨진다

## 검토한 대안과 기각 이유

- **스냅샷 있는 종목만 보너스 가점** — 데이터 유무가 점수가 되어 순위를 왜곡한다. 기각
- **ORCL 수치를 채워 전 종목 커버** — 공시를 직접 확인하지 않은 값을 채우는 건 날조다. 기각.
  값이 없으면 비워 두고 사용자에게 받는다

## 결과

상세 패널은 "판단 보조 자료"로 남고 점수는 재현 가능한 상태를 유지한다.
되돌리려면 `config.WEIGHTS` 에 항목을 추가하고 결측 종목 처리 규칙을 먼저 정해야 한다 —
그 규칙 없이 통합하는 것이 이 ADR이 막는 것이다.
